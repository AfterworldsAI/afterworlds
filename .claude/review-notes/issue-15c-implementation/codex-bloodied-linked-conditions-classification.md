### Bloodied — universal predicate, not runtime prose interpretation

**Verified authority.** `docs/sources/community/dnd-5e-srd-markdown/rules-glossary.md:269` defines Bloodied as half Hit Points or fewer. `playing-the-game.md:1142–1146` supplies the maximum/current context and repeats that Bloodied has no effect by itself. Accepted C5 represents `glossary.bloodied/bloodied` as prose-bound with `no_identified_structured_use`, without facts (`srd-5-2-1-corpus-8781d4e0-a3b-15c.json:233449–233458`). Its creature predicates already distinguish source and target Bloodied (`representation.py:4861–4867`) and standing-contributor subject Bloodied (`representation.py:5044`). The C5 capability specifically promises Berserker attack/save Advantage from recorded HP (`candidate-c5/capability.json:3818–3826`). Seven currently refused roster entries are explicitly named in `tests/pipeline/rpg/test_creature_roster.py:72–83`.

**Classification.** ADR-005d's central decision and Decisions 2/4 distinguish authoritative prose, fields required by a code-owned use, and hand-authored execution; they prohibit runtime inference of trusted values from prose. They do not require every universal adapter algorithm to be encoded as declarative data. ADR-015 Decision 7 assigns that execution to the hand-authored adapter. CRD Issue 15c explicitly owns code-derived predicates and exact source-bound certification. The existing Architecture Notes articulate universal arithmetic/sequencing as adapter procedure (`docs/architecture/issue-15c-bounded-d20.md:106–109`), although that wording still asks Codex to confirm the classification. **This review confirms that the universal Bloodied predicate belongs on that side of the boundary.** This is an interpretation of the governing contract, not a claim that the incomplete adapter is already certified.

ADR-005d's required-field rule (`adr-005d-complete-typed-mechanical-authority.md:159–161`) remains binding: if an operation needs a source data field, supply it before relying on the rule. Here the per-record predicates and effects are already typed; the shared half-HP comparison is the universal procedure applied to typed state. There is no runtime prose parser, numeric extraction or prose fallback, and this classification grants no execution of arbitrary prose-bound mechanics.

The missing item is the procedure and its certification, not an unknown threshold to ask the Owner to choose. Code can evaluate current HP against half the validated current maximum, with the existing maximum-reduction treatment and no temporary-HP addition. Integer comparison can avoid rounding ambiguity. Existing HP state separates these values (`models/dnd5e_state.py:427–440`; `pipeline/rpg/damage.py:314`). The predicate is computed when required from current, sequentially advanced state; it is not a model-supplied boolean or a new persisted condition.

**Required boundary.** Add the exact Bloodied and necessary HP-rule components to each affected operation's governing dependency set. Bind source identity, effective projection/overrides and adapter/manifest versions; missing or changed governing authority must refuse. The existing mechanism fingerprints override-aware component identities and rejects incompatible certification (`pipeline/rpg/capability.py:598–644`). Verify that the effective prose is included in those identities; a name or unchanged base-source hash alone is insufficient. Existing typed creature predicates continue to decide whose HP and which effect are involved. Do not infer missing per-entry qualifications or damage values from labels/prose.

A new typed Bloodied fact is an optional alternate representation; choosing that route would require a separately versioned, independently reviewed and exactly accepted semantic candidate. It is not necessary for this bounded procedure and must not be smuggled into accepted C7 or mutate C5. Do not generalize this classification into permission to hard-code missing per-record ammunition, grants, DCs or damage data.

**Observable proof.** Cover above/at/below half HP, odd maxima, reductions and temporary HP; source versus target identity; missing HP and changed/disabled authority; sequential HP changes within linked operations; the five named animal swarms, Crawling Claws and Berserker. Berserker's source also promises saving-throw Advantage: confirm that consumer rather than resolving only its Greataxe test. Keep all other named roster exclusions intact.

### Grappled → Restrained — bounded instance relationship

**Verified authority.** Purple Worm Bite (`monsters-A-Z.md:13632`) and Remorhaz Bite (`:14227`) apply Grappled to a Large-or-smaller target, with escape DC 19/17, and Restrained until that grapple ends. Accepted C5 already carries this exactly: oracle `:289935–289953` and `:286827–286845`. `LinkedCondition` and `LinkEnd.GRAPPLE_ENDS` are existing accepted source shapes (`representation.py:2197–2201`, `:4894–4900`). C5 classifies both Bites and Purple Worm's Multiattack as executable (`candidate-c5/capability.json:16377–16404`, `:17054–17061`). No missing source semantics need minting.

The actual gap is runtime state: `ConditionInstance` has a distinct instance ID, source, referent and `ends`, but `EffectEnd` has no condition-instance reference (`models/dnd5e_state.py:249–273`, `:489–512`). Creature preflight consequently rejects `rider.linked` (`pipeline/rpg/creature_attacks.py:356–379`). Existing clearing removes only directly addressed conditions (`services/dnd5e_state/effects.py:162–177`).

**Disposition.** Add the minimum typed runtime relationship that ties this Restrained instance to the Grappled instance created by the same source application on the same subject. Source semantics decide its lifetime. ADR-015 Decision 8 expressly requires sufficient duration/expiry metadata in sheet-owned state (`adr-015-rpg-adjudication.md:209–234`); CRD Issue 2b already preserves distinct condition instances and references (`issue-2b-character-state.md:45`). Extending that state within CRD Issue 15c's existing atomic delivery path fulfills those contracts. It does not change ownership, establish a general condition engine or add a competing pending/sequence model.

The implementation must preserve source size/DC/condition-immunity rules, valid instance references, independent concurrent grapples and unrelated Restrained instances. A linked condition must not outlive its own governing grapple, or be cleared when a different grapple ends. Ensure the invariant survives save/load, sequential effects and every existing supported path that removes or replaces conditions; dangling or malformed links must not silently become permanent restraint. Apply both creation and ending consequences within the same existing subject revision/binding/hold and delivery transaction. Keep hidden-state filtering intact. Let Claude select storage/helper details and the smallest validation change needed.

**Observable proof.** Both Bites and the admitted Purple Worm Multiattack execute; the same-grapple ending removes only its dependent instance; unrelated instances survive; restart/round-trip, invalid links, stale revisions and blocked-turn rollback preserve the contract. Exercise existing applicable condition-immunity cases without inventing a blanket rule that all linked mechanics share. Swallow, a general grapple/escape engine, arbitrary condition dependency graphs and other excluded entries are not admitted by this repair.
