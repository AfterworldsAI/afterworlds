## What is and is not already authoritative

- **The attack qualification exists.** Accepted C7 oracle `src/afterworlds/ingestion/mechanical/oracles/srd-5-2-1-corpus-8781d4e0-a3b-15c-c7.json:297580` has Ghoul `target_excludes=[undead, elf]`; `:302321` has Ghast `[undead]`. The source says exactly that (`docs/sources/community/dnd-5e-srd-markdown/monsters-A-Z.md:6756,6919`). The exclusion suppresses the rider save/effect, not the ordinary hit damage or the entire attack.
- **Target type is missing as source data.** Direct serialized-oracle inspection found no creature-type/species-tag fact family or nonempty `creature_type` component. Ghast/Ghoul profile components (`oracle:249071,251357`) contain abilities, defenses, immunities and size, but no type. Their source headers explicitly say Undead (`monsters-A-Z.md:6683,6851`). Elf and Human `creature_type` components remain `prose_bound`, `facts=[]`, `no_identified_structured_use` (`oracle:224703–224712` for Elf). The glossary type component is likewise prose-bound. The raw accepted C5-B Ghast profile also lacks type; this is not a native mapping omission. Native correspondence explicitly maps abilities, damage/condition defenses and sizes (`issue-15c-native/correspondence.md:90–96`), while source text/headings remain provenance, never minted facts (`:18`).
- **Typed state exists but does not prove the missing source assignment.** `Dnd5eCharacterState.creature_type` and `CreatureState.creature_type` use the closed source-backed vocabulary (`models/dnd5e_state.py:845,979`; `models/dnd5e_vocabulary.py:68`). Character validation checks species identity and kind (`services/dnd5e_state/validation.py:356–359`); creature validation checks template identity and shared state (`:478–495`). Neither proves the recorded type against a source assignment. Creature-state type specifically records a source-dependent departure from the template, such as a familiar's chosen type (`models/dnd5e_state.py:968–979`); it is not a universal trustworthy replacement for template type. CRD Issue 2b records state and explicitly does not certify legality (`docs/architecture/issue-2b-character-state.md:17–20,61`).
- **Elf identity is already represented.** `character_origins.elf` is an accepted `species` record (`oracle:1085490`); `OriginSelection` records its exact key (`models/dnd5e_state.py:281–286`), validated under the subject's binding. Thus the engineer's claim that no accepted authority types *species* is overstated. For an ordinary, unchanged character whose validated species identity is that exact record, matching the accepted `TargetTag.ELF` exclusion to it is bounded identity selection, not a new source fact or free-text classifier. Missing species, unexecuted forms/type-changing effects, or a creature instance whose species identity is unrepresented cannot be treated as “not Elf.” A creature-table row is not evidence of non-Elf status.
- **Certification supplies identity protection, not missing data.** `AuthorityIndex` reconstructs effective bound records (`services/dnd5e_state/authority.py:109–151`); template certification fingerprints effective components and refuses overridden templates (`pipeline/rpg/capability.py:598–632`). Neither manufactures a creature-type assignment. New dependencies must use each affected subject's own binding and current state, including source-qualified overrides/forms; don't borrow the attacker's type, infer from a record name, or trust an arbitrary stored enum.

## Why Bloodied does not remove this prerequisite

ADR-005d Decisions 2/4 require needed fields before code relies on a rule and prohibit runtime prose-derived trusted values (`docs/decisions/adr-005d-complete-typed-mechanical-authority.md:159–161,181–202`). The classifier distinguishes **per-record data** from universal arithmetic/sequencing (`gap-inventory.md:13–25`). The prior Bloodied classification permits one universal half-HP comparison over already typed HP; it expressly excludes hard-coding missing per-record data (`codex-bloodied-linked-conditions-classification.md:17–23`).

Comparing an authoritative type to `UNDEAD` is ordinary adapter procedure. Establishing “this template/species is type X” is the missing per-record input. A compiled lookup extracted from headers would still introduce those new source assignments; pinning its source hash does not turn it into the Bloodied procedure. Nor does the source's general statement that the Character Origins species are Humanoid authorize skipping representation: it is authoritative meaning requiring a typed source assignment/group fact for this newly identified use (`character-origins.md:79–81`). No existing accepted typed primitive inspected here supplies that assignment.

The approved GM spatial/time/hand inputs do not authorize new type/species assertions. Broadening GM truth authority would be a separate policy decision, and is unnecessary for source-defined base types. Do not conflate mechanical creature type with the separate character/monster zero-HP classification or pet treatment.
