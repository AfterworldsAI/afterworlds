## Exact inference and its limits

The source explicitly makes creature type a species characteristic (`character-origins.md:77–81`) and assigns Elf **Humanoid** (`:180–186`). C8 r2 represents that exact assignment (`candidate-c8/c8.json:1461–1472`). The glossary identifies type as a rules tag for every creature (`rules-glossary.md:515–549`); monster headers state that type (`monsters.md:7,31–35`). Therefore, within the unchanged ordinary-species domain:

`Elf ⇒ Humanoid; authoritative applicable type ≠ Humanoid ⇒ not Elf`.

This does not infer identity from a missing tag, a table name, a creature label, or the converse `Humanoid ⇒ Elf`. It does not identify the target's particular non-Elf species. It establishes only the negative predicate needed by Ghoul Claw. Once both input assignments are accepted and certified, requiring an additional Owner-approved negative-species fact would be unnecessary. Before C8 acceptance, the missing typed input remains a real gate.

The source does **not** make this an unrestricted theorem about any field called current type. It gives effect-specific transformation rules (`rules-glossary.md:1275`). Wild Shape explicitly retains type (`classes.md:3505`), as do Animal Shapes, Polymorph and Shapechange (`spells.md:373,4165,4890`); an Elf in one of those Beast-looking forms is not proved non-Elf by the form's Beast header. True Polymorph replaces statistics with a different retention list (`spells.md:5662–5666`), and Mask explicitly distinguishes actual type from how effects treat the target (`:597–599`). These examples establish the need for source-specific handling; this report makes no new judgment about whether Ghoul's Elf exception survives any particular unexecuted transformation.

## What must prove the ordinary domain

Use the subject's own exact binding, certified profile/species facts, current revision and applicable primitive state. `CreatureState.template_record_key` identifies the stat block the subject is an instance of; its optional type field records source-dependent departures, not universal replacement authority (`models/dnd5e_state.py:967–979`). Certification is already routed through the subject's own index (`pipeline/rpg/defense.py:236–244`), but cannot manufacture missing type or form facts.

**Explicitly recorded empty effects are different from absent state.** The state contract makes `None` unrecorded and `()` recorded empty (`models/dnd5e_state.py:8–14`); creature readiness requires active effects (`services/dnd5e_state/validation.py:597–606`). Ordinary execution can use that recorded state with a certified base template and validated source consistency. It cannot treat no `form_record_key`, no recorded type override, or an unrecorded effect family as proof that the subject is unchanged. Where a known source/form departure cannot be expressed or validated, keep that case held; this does not make every ordinary base target unsupported.

Current shared validation verifies an effect's source identity/selections and any form-record identity, and validates summon source identity (`validation.py:334–340,479–495`). These are necessary identity checks, **not** effective type/species derivation. Existing `other_effects` filters only on three mastery source keys and treats absent effects like empty (`pipeline/rpg/mastery.py:43–54`). It is not by itself proof of the unchanged domain, nor proof that an arbitrary recorded form on an allowlisted source is legitimate. The later type-dependent path must preserve missing-state refusal and validate any contributing source/form relationship before applying the inference or an exclusion shortcut. This is ordinary fail-closed validation under AC3/4/6, not a new Owner policy. No runtime bypass finding or full-path clearance is claimed here.
